Guia completo do Formulario de Matricula

Este guia explica a estrutura do projeto do professor, o papel de cada arquivo, a semantica do formulario, a organizacao do CSS, o uso de rem no lugar de pixels soltos, o uso de SVG nos campos, seletores WebKit e o padrao que seus proximos projetos devem seguir.

A partir de agora

Seus proximos projetos devem seguir esta ideia de estrutura

O projeto ficou mais profissional porque separa responsabilidades. O HTML descreve o conteudo e os grupos do formulario. O CSS fica dividido por funcao: base global, layout da pagina, formulario e campos especificos. Essa separacao evita um arquivo gigante dificil de manter.

1. HTML semantico

Use tags reais para o papel real: `main`, `aside`, `form`, `fieldset`, `legend`, `label`, `input`, `select`, `textarea` e `button`.

2. CSS por responsabilidade

Um arquivo para reset/tokens, um para layout, um para formulario e arquivos menores para componentes repetidos.

3. Assets organizados

Imagens, logos e icones ficam dentro de `assets`, separados por tipo quando o projeto cresce.

Estrutura de arquivos

A pasta do projeto foi dividida para cada arquivo ter uma missao

A estrutura abaixo e a referencia principal para formularios grandes. O `index.html` monta a tela. O `styles/index.css` apenas importa os outros arquivos. A pasta `fields` guarda estilos de campos especificos.

`index.html`

Arquivo principal da pagina. Ele carrega fonte, CSS, layout, formulario e painel lateral.

`assets/`

Guarda os arquivos visuais usados pela pagina: logo, ilustracao e icones dos campos.

`styles/index.css`

Arquivo de entrada do CSS. Ele importa `global.css`, `layout.css` e `forms.css`.

`styles/fields/`

Separacao dos componentes de campo: input, upload, radio, checkbox e botoes.

HTML geral

O HTML foi separado em duas grandes regioes: formulario e painel visual

Dentro do `body`, o projeto usa uma div principal chamada `#app`. Ela recebe o grid de duas colunas no CSS. A primeira coluna e o `main`, onde fica o formulario. A segunda coluna e o `aside`, usado para a marca, frase institucional e ilustracao. 

<body>
  <div id="app">
    <main>
      <div class="main-container">
        <div class="back">...</div>
        <h1>Formulario de matricula</h1>
        <p>Texto de introducao</p>

        <form method="post" enctype="multipart/form-data">
          ...
        </form>
      </div>
    </main>

    <aside>
      <div class="aside-container">
        ...
      </div>
    </aside>
  </div>
</body>

Por que `main`?

`main` representa o conteudo principal da pagina: o formulario que o usuario precisa preencher.

Por que `aside`?

`aside` representa conteudo complementar. A ilustracao e a frase ajudam a marca, mas nao sao o formulario em si.

Estrutura do formulario

`form`, `fieldset`, `legend` e `label` deixam o codigo mais semantico

Um formulario grande nao deve ser uma lista solta de inputs. O projeto agrupa os campos por assunto usando `fieldset`. O titulo de cada grupo fica em `legend`. Cada campo recebe um `label` conectado ao input pelo par `for` e `id`. 

<fieldset class="child-info">
  <legend>Informacoes da crianca</legend>

  <div class="input-wrapper">
    <label for="fullname">Nome completo</label>
    <input id="fullname" name="fullname" type="text" />
  </div>
</fieldset>
Parte Funcao Por que usar
`form` Envolve todos os campos enviados. Permite submit, validacao nativa e envio organizado.
`fieldset` Agrupa campos relacionados. Melhora leitura, acessibilidade e organizacao visual.
`legend` Nomeia o grupo do fieldset. Ajuda o usuario e tecnologias assistivas a entenderem o bloco.
`label` Da nome ao campo. Ao clicar no texto, o input correto recebe foco.
`name` Nome do dado enviado. Sem `name`, o valor do campo nao vai corretamente no envio.
Blocos do formulario

Cada fieldset representa uma etapa mental do preenchimento

1

`child-info`

Dados da crianca: nome, data de nascimento, sexo, informacoes medicas e certidao.

2

`address`

Endereco residencial. Usa linhas flexiveis para rua/numero e cidade/estado.

3

`gardian`

Dados do responsavel. O campo de e-mail usa `required` e mensagem de erro visual.

4

`enroll-options`

Turno e esportes. Usa inputs radio dentro de cards personalizados.

5

Termos e acoes

Checkbox de aceite, botao secundario para salvar e botao primario para enviar.

CSS principal

`styles/index.css` e um arquivo de entrada, nao um lugar para tudo

O arquivo `styles/index.css` tem apenas imports. Essa escolha faz com que o HTML carregue um unico CSS, mas o desenvolvimento continue organizado em arquivos menores. 

@import url(global.css);
@import url(layout.css);
@import url(forms.css);

O `forms.css`, por sua vez, importa `fields/index.css`, e esse arquivo importa os estilos especificos de cada tipo de campo. Assim o CSS forma uma arvore facil de navegar. 

forms.css
  imports fields/index.css

fields/index.css
  imports input.css
  imports droparea.css
  imports radio.css
  imports checkbox.css
  imports buttons.css
Global CSS

`global.css` guarda reset, variaveis e utilitarios pequenos

O reset remove margem e padding padrao do navegador. As variaveis em `:root` centralizam cores, fontes e tokens. As classes `.flex`, `.flex-1` e `.flex-2` sao utilitarios pequenos para evitar repeticao. 

* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}

:root {
  --font-family: "Poppins", sans-serif;
  --text: 400 1rem/1.5 var(--font-family);
  --text-sm: 400 0.875rem/1.4 var(--font-family);

  --text-primary: #292524;
  --text-secondary: #57534e;
  --text-highlight: #e43a12;
}
Por que variaveis?

Se a cor de destaque mudar, voce troca uma vez em `:root` e o projeto inteiro acompanha.

Layout CSS

`layout.css` cuida da pagina, nao dos inputs

O `#app` usa CSS Grid com duas colunas. A primeira ocupa `51.25%` e a segunda `48.75%`. Esses valores reproduzem a proporcao do layout do Figma. O `main` tem scroll proprio, enquanto o `aside` fica como painel visual. 

#app {
  display: grid;
  grid-template-columns: 51.25% 48.75%;
  height: 100vh;
  overflow: hidden;
}

main {
  overflow: auto;
  padding: 4rem;
}

aside {
  background-color: var(--surface-secondary);
  padding: 4rem;
}

Repare no `padding: 4rem`. Como `1rem` normalmente vale `16px`, `4rem` equivale a `64px`, que e um espacamento comum vindo do Figma.

Forms CSS

`forms.css` organiza o ritmo vertical do formulario

O formulario ganha margem no topo, os fieldsets viram grids com gap, e `fieldset + fieldset` aplica distancia apenas entre um grupo e outro. Isso e melhor do que colocar margem manual em cada bloco. 

form {
  margin-top: 3rem;
}

fieldset {
  border: none;
  display: grid;
  gap: 1.5rem;
}

fieldset + fieldset {
  margin-top: 3rem;
}
Detalhe importante

`fieldset + fieldset` significa: aplique a regra em um fieldset que vem imediatamente depois de outro fieldset.

Campos base

`input.css` cria o estilo padrao de input, select e textarea

O professor usa uma regra compartilhada para `input`, `textarea` e `select`. Isso garante largura, borda, raio, padding e fonte iguais. Depois ele trata casos especiais como foco, data, select, disabled, invalid e erro. 

input,
textarea,
select {
  appearance: none;
  width: 100%;
  border-radius: 0.5rem;
  border: 2px solid transparent;
  outline: 1px solid var(--stroke-default);
  padding: 0.75rem 1rem;
  font: var(--text);
}

`appearance: none`

Remove parte do estilo padrao do navegador para o campo ficar mais controlavel.

`outline` + `border`

Permite criar foco bonito sem mexer no tamanho total do campo.

`input:focus`

Destaca o campo ativo usando cor de borda e fundo suave.

`input:invalid`

Usa a validacao nativa do HTML para aplicar borda vermelha.

Select, date e WebKit

O professor removeu controles nativos para desenhar icones proprios

Alguns campos, como `select` e `input type="date"`, ja nascem com aparencia propria do navegador. O problema e que cada navegador pode desenhar esses controles de um jeito. Por isso o projeto usa `appearance: none` para limpar parte do visual nativo e depois coloca icones SVG proprios com `background` e pseudo-elementos. 

select {
  background: url(../../assets/icons/arrow-down-01.svg) no-repeat calc(100% - 1rem);
}

Nesse caso, o `select` perdeu a seta padrao e ganhou uma seta SVG como imagem de fundo. O `calc(100% - 1rem)` posiciona o icone perto da borda direita, deixando `1rem` de respiro. 

input[type="date"] {
  position: relative;

  &::-webkit-calendar-picker-indicator {
    opacity: 0;
  }

  &::before {
    content: "";
    position: absolute;
    background: url(../../assets/icons/calendar-03.svg) center/contain;
    right: 1rem;
    width: 1.25rem;
    height: 1.25rem;
    top: 50%;
    transform: translateY(-50%);
  }
}

`::-webkit-calendar-picker-indicator`

Seleciona o icone nativo do calendario em navegadores baseados em WebKit/Blink, como Chrome, Edge e Safari.

`opacity: 0`

Esconde o icone nativo, mas o campo continua sendo um `input type="date"` real.

`::before`

Cria um icone visual novo, usando o SVG `calendar-03.svg` como background.

Por que WebKit?

Porque esse pedaco interno do campo de data nao tem um seletor padrao igual em todos os navegadores.

Importante

`-webkit` ou `::-webkit-*` nao e biblioteca e nao precisa instalar nada. E um prefixo/seletor especifico de navegador. Use apenas quando precisar controlar uma parte interna que o CSS padrao nao alcanca bem.

Upload

`droparea.css` transforma um input file em uma area clicavel

O input de arquivo real continua existindo, mas fica invisivel e ocupa toda a area. A div `.dropzone` mostra o visual: borda tracejada, icone e texto. Quando o usuario passa o mouse ou foca o input, a area muda de cor. 

.dropzone {
  border: 2px dashed transparent;
  outline: 1px dashed var(--stroke-default);
  display: grid;
  justify-items: center;
  position: relative;
}

.dropzone input {
  position: absolute;
  width: 100%;
  height: 100%;
  inset: 0;
  opacity: 0;
}
SVG e cores

O projeto usa SVG de dois jeitos diferentes, e isso muda como a cor funciona

A explicacao de SVG e cores aparece aqui na pratica. Quando o SVG esta direto no HTML, o CSS consegue mirar em partes internas como `path` e trocar `stroke` ou `fill`. Quando o SVG entra como `img` ou `background-image`, o CSS da pagina nao consegue alterar facilmente o `path` interno do arquivo. Por isso o projeto troca o arquivo inteiro em estados diferentes.

SVG inline

Usado na area de upload. Como o SVG esta dentro do HTML, o CSS consegue fazer `.dropzone svg path { stroke: ... }`.

SVG como imagem

Usado em radio e checkbox. Como entra por `background-image`, o projeto troca entre `default`, `hover` e `checked`.

.dropzone:hover svg path {
  stroke: var(--stroke-highlight);
}

.radio-inner .radio-image {
  background-image: url(../../assets/icons/radio-default.svg);
}

.radio-inner:has(:checked) .radio-image {
  background-image: url(../../assets/icons/radio-checked.svg);
}

`fill`

Pinta a parte interna de uma forma SVG.

`stroke`

Pinta a linha ou contorno de uma forma SVG.

`currentColor`

Faz o SVG herdar a cor do texto, mas precisa estar preparado no proprio SVG.

Troca de arquivo

Boa solucao quando o icone esta como `background-image` e voce quer estados visuais diferentes.

Regra pratica

Se precisar trocar cor via CSS, prefira SVG inline ou SVG preparado com `currentColor`. Se estiver usando `img` ou `background-image`, use arquivos separados para cada estado visual.

Radio cards

`radio.css` faz radios parecerem cards selecionaveis

Cada `.radio-inner` e um card. O `input` fica absoluto e ocupa todo o card, mas o visual do radio e feito por `.radio-image`, trocando imagem conforme hover, foco e checked. 

.radio-inner {
  border: 1px solid var(--stroke-default);
  border-radius: 0.5rem;
  display: grid;
  justify-items: center;
  position: relative;
}

.radio-inner:has(:checked) {
  border: 2px solid var(--stroke-highlight);
}
O que e `:has()`?

`:has(:checked)` quer dizer: estilize o card quando ele tiver dentro dele um input marcado.

Checkbox e botoes

Checkbox e botoes seguem a mesma logica de componente

O checkbox usa um input invisivel e uma imagem visual que muda quando o input esta marcado. Os botoes usam `all: unset` para remover estilos padrao do navegador e depois recebem variantes: `.btn-primary` e `.btn-secondary`. 

.checkbox-wrapper [type="checkbox"] {
  all: unset;
  position: absolute;
  inset: 0;
}

.checkbox-wrapper:has(:checked) .checkbox-image {
  background-image: url(../../assets/icons/checkbox-checked.svg);
}

button.btn-primary {
  color: white;
  background-color: #e43a12;
}
Nesting CSS

O projeto usa aninhamento com `&` para escrever seletores ligados

Em alguns arquivos aparece CSS assim: `main { & .main-container { ... } }`. O `&` representa o seletor pai. Entao `& .main-container` vira `main .main-container`. Isso reduz repeticao, mas deve ser usado com cuidado para nao criar seletores longos demais. 

main {
  padding: 4rem;

  & .main-container {
    max-width: 33rem;
    margin-left: auto;
  }
}

Padrao recomendado: use nesting quando o filho so faz sentido dentro daquele bloco. Se o componente sera reutilizado em outros lugares, prefira uma classe propria.

Rem e pixel

Use `rem` para transformar medidas do Figma em valores mais flexiveis

Por padrao, navegadores usam `16px` como tamanho base de fonte. Entao `1rem` normalmente equivale a `16px`. O projeto usa bastante `rem` porque ele respeita configuracoes de acessibilidade do usuario e evita uma chuva de pixels soltos no CSS.

Pixel no Figma Valor em rem Uso comum
64px `4rem` Padding grande da pagina.
48px `3rem` Distancia entre blocos grandes.
32px `2rem` Padding interno de cards ou grupos.
24px `1.5rem` Gap entre campos.
16px `1rem` Texto base e padding horizontal.
14px `0.875rem` Texto menor, label e ajuda.
12px `0.75rem` Padding vertical de inputs.
8px `0.5rem` Border radius e gaps pequenos.
4px `0.25rem` Gap entre label e campo.
Regra pratica

Use `rem` para fonte, padding, margin, gap e radius. Use `px` principalmente para bordas finas como `1px` e ajustes muito especificos.

Checklist final

Antes de considerar um projeto finalizado, confira estes pontos

  1. O `index.html` tem estrutura semantica clara?
  2. O CSS principal apenas importa os arquivos menores?
  3. Existe `global.css` com reset, variaveis e fonte base?
  4. O layout da pagina esta separado dos estilos de componentes?
  5. Campos repetidos compartilham classes e regras base?
  6. Medidas grandes do Figma foram convertidas para `rem`?
  7. Bordas finas continuam em `px` quando fizer sentido?
  8. Assets estao dentro de `assets`, sem caminhos espalhados?
  9. O projeto abre localmente pelo `index.html` antes de ser considerado finalizado?
