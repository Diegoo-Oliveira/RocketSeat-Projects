Tutorial de projeto

Como montar o Formulario de Convite usando HTML e CSS em REM

Este roteiro mostra como criar o projeto "Formulario de convite" com base no projeto "Formulario de matricula". A ideia e manter a mesma organizacao: primeiro montar todo o HTML, depois separar o CSS em varios arquivos pequenos, cada um cuidando de uma parte da tela.

Regra deste projeto

Vamos pensar somente em PC e usar REM como medida principal

Neste tutorial voce nao precisa criar versao mobile. O foco e montar a tela para desktop, igual ao layout do Figma. Ainda assim, usar rem e uma boa pratica porque os tamanhos ficam baseados na fonte raiz do navegador.

Por padrao, os navegadores usam 16px como tamanho base. Entao a conta mais comum e simples: divida o valor em pixels por 16. Exemplo: 560px / 16 = 35rem.

Leitura do Figma

Antes de codar, leia o layout como duas grandes regioes

O frame principal do Figma tem uma tela de desktop com 1280px de largura, ou seja, 80rem. Dentro dele existem duas partes principais: a coluna da marca, chamada Brand, e a coluna do formulario, chamada Invite.

Essa leitura decide o seu layout.css: o container principal usa display: grid, a primeira coluna tem 25rem e a segunda fica com o restante do espaco.

HTML explicado

Entenda cada parte do HTML antes de ir para o CSS

1. Head

O head carrega fonte, titulo e o arquivo styles/index.css. Esse arquivo sera o concentrador dos imports de CSS.

2. #app

O #app e o container geral. Ele vai virar o grid com duas colunas: marca na esquerda e formulario na direita.

3. Aside .brand

O aside guarda o lado visual do layout: logo, titulo Festivite, frase e imagem de fundo. Ele nao faz parte do formulario.

4. Main .invite

O main guarda a area principal da pagina. Dentro dele, .invite-container limita o formulario em 35rem, que equivale aos 560px do Figma.

5. Fieldsets

Cada grupo grande vira um fieldset: sobre o evento, personalizacao e contato. O titulo do grupo fica no legend.

6. Wrappers

Classes como .input-wrapper, .form-row e .theme-grid servem para organizar visualmente os campos sem mudar a semantica do formulario.

CSS por arquivos

Agora separe o CSS por responsabilidade

Pense no CSS como gavetas. Uma gaveta guarda tokens e reset. Outra guarda o layout da pagina. Outra guarda os espacamentos do formulario. E as outras guardam componentes pequenos, como input, cores, temas, switch, upload, checkbox e botao.

styles/index.css

Arquivo que junta todos os outros CSS

Esse arquivo funciona como a porta de entrada. No HTML voce importa apenas ele, e ele importa os demais arquivos na ordem correta. 

@import url(global.css);
@import url(layout.css);
@import url(forms.css);
@import url(fields/index.css);

Aqui ficam os estilos globais e as variaveis. Use nomes que expliquem a funcao da cor, nao apenas o tom. Por exemplo: --text-heading e melhor do que --white.

Se voce precisar mudar a cor principal depois, troca apenas a variavel. Se espalhar o codigo hexadecimal em varios arquivos, fica muito mais dificil manter o projeto.

Inputs, labels e textarea

Este e o componente mais reutilizado. Todo campo comum do formulario usa .input-wrapper, depois label e input ou textarea.

Por que o gap fica no wrapper?

Porque o wrapper controla a distancia entre label e campo. Assim o input nao precisa saber se tem um texto acima dele.

Ordem para construir

Use esta sequencia para nao se perder

  1. Crie a pasta formulario-de-convite.
  2. Crie o index.html e cole a estrutura geral.
  3. Crie a pasta styles e o arquivo styles/index.css.
  4. Crie global.css com reset, fontes, cores e variaveis.
  5. Crie layout.css para dividir a tela em duas colunas.
  6. Crie forms.css para fieldsets, legends, linhas e rodape.
  7. Crie os arquivos dentro de fields, um por componente.
  8. Teste visualmente no navegador e compare com o Figma.
  9. So depois troque placeholders por icones e imagens reais.
