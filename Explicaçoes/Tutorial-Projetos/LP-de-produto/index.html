Tutorial – LP de Produto

Como construir a Landing Page do Zingen

Este roteiro explica como transformar o layout do Figma em código HTML e CSS organizado. O projeto usa CSS modular (um arquivo por seção), utilitários reutilizáveis e a técnica de CSS aninhado nativo (sem pré-processadores). Siga passo a passo para entender cada decisão de estrutura.

Leitura do layout

Identifique as seções antes de escrever código

O primeiro passo é ler o Figma e separar a página em grandes blocos. O Zingen tem exatamente 7 seções principais — cada uma vira uma tag <section> no HTML com um id próprio.

Perceba que o header e o footer ficam fora das sections, pois são elementos globais da página.

Seções do projeto

  1. header / nav – logo + links de navegação + botão CTA
  2. #hero – ícone musical + h1 + subtítulo + botões
  3. #smartphones-img – imagem decorativa dos celulares
  4. #about – eyebrow + título + texto + mockup (two columns no desktop)
  5. #features – 5 cards em grid de 4 colunas (só desktop)
  6. #pricing – header + 3 cards de plano (Básico, Premium, Família)
  7. #download – CTA de download com botões App Store e Play Store
  8. footer – logo + 3 colunas de links + redes sociais

Mapa visual da página

header (logo + nav links + btn)
hero (ícone + h1 + subtítulo + botões)
smartphones-img (imagem decorativa)
about (texto | mockup)
card 1 card 2 (2 cols) card 3 card 4 (2 cols) card 5 (2 cols)
Básico Premium ⭐ Família
download (CTA + stores)
footer (logo + links + social)
Passo 0

Estrutura de pastas e arquivos

Este projeto usa CSS modular: cada seção da página tem seu próprio arquivo CSS. O arquivo index.css importa todos usando @import. Isso facilita encontrar e editar o estilo de qualquer parte sem buscar em um arquivo gigante.

Detalhe importante: o features.css é importado com condição de media query diretamente no @import: @import url(features.css) (width >= 80em); Isso significa que o CSS de features só é aplicado em telas largas — no mobile, o layout padrão (cards empilhados) já vem do HTML + cards.css.

Passo 1 – global.css

Variáveis, reset e tipografia base

O global.css define o design system completo: cores, fontes, tamanhos e espaçamentos. Use variáveis CSS para tudo — assim você muda um valor e o site inteiro se atualiza.

1

Variáveis de cor e tipografia

Todas as cores e fontes do projeto ficam no :root.

:root {
  /* Cores */
  --bg-color: #09090b;          /* fundo escuro da página */
  --surface-color: #18181b;     /* fundo dos cards */
  --stroke-color: #27272a;      /* bordas e separadores */
  --text-color-primary: #f4f4f5;
  --text-color-secondary: #a1a1aa;
  --brand-color-primary: #f7b733;   /* amarelo */
  --brand-color-secondary: #fc4a1a; /* laranja-avermelhado */

  /* Fonte */
  --ff-sans: 'Inter', system-ui, sans-serif;
  --fw-base: 400;
  --fw-md: 500;
  --fw-bold: 800;

  /* Tamanhos de fonte (mobile) */
  --fs-sm: 0.875rem;
  --fs-base: 1rem;
  --fs-lg: 1.25rem;
  --fs-xl: 1.5rem;
  --fs-2xl: 2.5rem;

  /* Espaçamentos */
  --py-base: 1rem;
  --py-lg: 1.5rem;
  --py-xl: 3rem;
  --px-lg: 1.5rem;
}
2

Escalar para desktop com uma única @media

No desktop (≥ 80em = 1280px), as variáveis de fonte e espaçamento aumentam. Todo o site que usa var(--fs-2xl) cresce automaticamente. 

@media (width >= 80em) {
  :root {
    --fs-lg: 2rem;
    --fs-xl: 3rem;
    --fs-2xl: 4rem;

    --py-base: 1.5rem;
    --py-lg: 2.5rem;
    --py-xl: 5rem;
    --px-lg: 2rem;
  }
}

Isso é diferente do mobile-first clássico: as variáveis base já existem, e apenas seus valores mudam no desktop. É uma abordagem híbrida mas muito limpa.

3

Reset e estilos de elementos globais

*, *::before, *::after {
  box-sizing: border-box;
}

* {
  margin: 0;
  padding: 0;
  font: inherit;                 /* herda fonte do pai, elimina user-agent */
  -webkit-font-smoothing: antialiased;
}

a {
  text-decoration: none;
  color: inherit;
}

/* Efeito hover de gradiente em todos os links */
a:hover {
  background: linear-gradient(
    90deg,
    var(--brand-color-secondary) 0%,
    var(--brand-color-primary) 100%
  );
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
}

img {
  max-width: 100%;
  display: inline-block;
}

ul[role='list'] {
  list-style: none;   /* remove bullets apenas quando role=list */
}

font: inherit no reset universal é uma técnica moderna: elimina o estilo de fonte padrão do navegador em input, button, select etc. Você não precisa mais de font-family: inherit em cada campo.

Passo 2 – utility.css

Classes utilitárias: container, flex, grid e even-columns

Em vez de repetir display: flex e gap: 1rem em cada seção, o projeto cria classes utilitárias que são compostas diretamente no HTML. Essa é a base do design system.

1

O .container centraliza e limita a largura

.container {
  --max-width: 375px;                    /* mobile: largura máxima */
  width: min(var(--max-width), 100% - var(--px-lg) * 2);
  margin-inline: auto;
}

@media (width >= 80em) {
  .container {
    --max-width: 80rem;                  /* desktop: 1280px */
  }
}

min() garante que o container nunca ultrapasse --max-width, mas também nunca quebre a margem lateral. É uma alternativa elegante ao clássico max-width + padding.

2

.even-columns: grid que vira colunas no desktop

/* Mobile: empilhado */
.even-columns {
  display: grid;
  gap: 1rem;
}

/* Desktop: colunas iguais lado a lado */
@media (width >= 80em) {
  .even-columns {
    grid-auto-flow: column;
    grid-auto-columns: 1fr;
  }
}

grid-auto-flow: column faz os itens irem para novas colunas (em vez de linhas). Combinado com grid-auto-columns: 1fr, cada filho ocupa a mesma largura — independente de quantos forem. Não precisa declarar grid-template-columns.

3

Utilitários de espaçamento e layout

/* Padding vertical */
.py-base { padding-block: var(--py-base); }
.py-lg   { padding-block: var(--py-lg); }
.py-xl   { padding-block: var(--py-xl); }

/* Padding horizontal */
.px-lg   { padding-inline: var(--px-lg); }

/* Flexbox rápido */
.flex         { display: flex; }
.items-center { align-items: center; }
.gap-1        { gap: 1rem; }
.gap-1\.5     { gap: 1.5rem; }

/* Grid rápido */
.grid { display: grid; }

/* Visibilidade */
.desktop-only { display: none; }
@media (width >= 80em) {
  .desktop-only { display: initial; }
}
Passo 3 – buttons.css

O componente .btn e a técnica do aria-label

O projeto usa uma técnica avançada para botões que precisam de borda gradiente: o texto vem do atributo aria-label via CSS content: attr(aria-label). Isso mantém a acessibilidade e elimina texto vazio no HTML.

1

Estrutura base do .btn

.btn {
  --btn-bg-color: var(--text-color-primary);
  --btn-color: var(--bg-color);

  display: flex;
  align-items: center;
  justify-content: center;
  width: fit-content;
  border: 0;
  border-radius: 0.5rem;
  background: var(--btn-bg-color);
  color: var(--btn-color);
  font: var(--fw-md) var(--fs-base) / 1.5rem var(--ff-sans);
  cursor: pointer;
}

/* Hover: gradiente vira o fundo */
.btn:hover {
  --btn-bg-color: linear-gradient(
    90deg,
    var(--brand-color-secondary) 0%,
    var(--brand-color-primary) 100%
  );
  --btn-color: var(--surface-color);
  color: var(--btn-color);
}
2

Variantes de tamanho

.btn-sm  { padding: 0.5rem 1rem;   font-size: var(--fs-sm); }
.btn-md  { padding: 0.75rem 1.5rem; font-size: var(--fs-base); }
.btn-lg  { padding: 1rem 2rem;     font-size: 1.125rem; }

@media (width >= 80em) {
  .btn-sm { padding: 0.75rem 1.5rem; font-size: var(--fs-base); }
  .btn-md { padding: 1rem 2rem;     font-size: 1.125rem; }
}
3

A técnica do botão com borda gradiente

Quando um .btn tem aria-label, ele vira um botão com borda gradiente. O truque usa três camadas:

  1. O elemento .btn recebe o gradiente como background
  2. O ::before cobre o interior com a cor de fundo, criando o efeito de borda
  3. O ::after exibe o texto do aria-label com gradiente no texto
/* No HTML — botão sem texto visível */
<a href="#pricing" aria-label="Ver planos" class="btn btn-md"></a>

/* No CSS */
.btn[aria-label] {
  position: relative;

  /* Camada 1: cobre o interior para criar a "borda" */
  &::before {
    content: '';
    position: absolute;
    border-radius: inherit;
    inset: 1px;                      /* 1px menor que o btn em todos os lados */
    background-color: var(--bg-color);
  }

  /* Camada 2: texto vem do aria-label com gradiente */
  &::after {
    content: attr(aria-label);
    background: var(--btn-bg-color);
    -webkit-background-clip: text;
    background-clip: text;
    color: transparent;
    position: relative;
    z-index: 1;                      /* fica acima do ::before */
  }
}

Por que usar aria-label? O elemento fica semanticamente acessível (leitores de tela lêem o atributo), o HTML fica limpo sem texto vazio, e o CSS puxa o conteúdo automaticamente com content: attr(aria-label).

Passo 4 – HTML

Estrutura HTML: composição de classes no markup

A grande sacada do projeto é compor as classes utilitárias diretamente no HTML. Uma <div> pode ter várias classes ao mesmo tempo — cada uma contribui com um comportamento específico.

1

Header / nav

<header>
  <div class="container py-base">
    <nav class="flex items-center gap-1.5">
      <a href="#">
        <img src="assets/logo.svg" alt="Logo Zingen" />
      </a>

      <!-- Só aparece no desktop (.desktop-only) -->
      <a href="#about" class="desktop-only">Conheça o app</a>
      <a href="#features" class="desktop-only">Funcionalidades</a>
      <a href="#pricing" class="desktop-only">Planos e preços</a>

      <!-- Sempre visível: CTA de download -->
      <a href="#download" class="btn btn-sm">Baixar agora</a>
    </nav>
  </div>
</header>

container py-base = centraliza a largura + padding vertical. flex items-center gap-1.5 = nav em linha com espaço entre itens. Os links de navegação usam desktop-only para aparecer apenas em telas largas.

2

Seção Hero

<section id="hero">
  <div class="container py-xl">
    <img src="assets/music-bars.svg" alt="" />
    <h1>Quem canta seus males espanta</h1>
    <p>Cantar nunca foi tão fácil</p>

Note os dois tipos de botão lado a lado: um com aria-label (borda gradiente) e um com texto normal (fundo sólido). O hero.css adiciona text-align: center e espaça os elementos.

3

Seção About (duas colunas no desktop)

<section id="about">

        <strong>Conheça o app</strong>

even-columns empilha no mobile e cria 2 colunas iguais no desktop. items-center alinha verticalmente texto e imagem. O <header> dentro da section organiza eyebrow + título — o sections.css estiliza esse padrão globalmente.

Passo 5 – features.css

O grid de funcionalidades: layout só no desktop

Esta é a seção mais complexa. No mobile, os 5 cards ficam empilhados (isso vem do cards.css + layout padrão do HTML). No desktop, o features.css monta um grid de 4 colunas × 2 linhas com cards de tamanhos diferentes.

1

HTML dos cards de features

<section id="features">
  <div class="cards container py-xl grid gap-1.5">
    <!-- Card pequeno: ocupa 1 coluna -->
    <div class="card py-lg px-lg">
      <img src="assets/icons/MagicWand.svg" alt="" />
      <h3>A maior biblioteca de músicas de Karaokê!</h3>
      <p>...</p>
    </div>

    <!-- Card grande: ocupa 2 colunas no desktop -->
    <div class="card py-lg px-lg">
      <div> <!-- texto fica limitado a max-width: 16rem -->
        <img src="assets/icons/GameController.svg" alt="" />
        <h3>Experiência gamificada</h3>
        <p>...</p>
      </div>
      <!-- Imagem de tela (só aparece no desktop) -->
      <img class="desktop-only" src="assets/Tela 2.png" alt="" />
    </div>
    <!-- ... mais 3 cards -->
  </div>
</section>
2

O grid de 4 colunas no features.css

Lembre: este arquivo só carrega em telas ≥ 80em (por causa do @import url(features.css) (width >= 80em) no index.css). 

#features {
  /* Grid: 2 colunas de 17.5rem + 2 fracionadas = 4 colunas no total */
  & .cards {
    grid-template-columns: 17.5rem 1fr 1fr 17.5rem;
    grid-template-rows: 25rem 25rem;
    gap: 2rem;
  }

  & .card {
    position: relative;    /* para imagens com position: absolute */
    overflow: hidden;

    & img.desktop-only {
      position: absolute;
      max-width: 15rem;
      filter: drop-shadow(1rem 1rem 4rem rgb(0 0 0 / 0.34));
    }
  }

  /* Linha 1 */
  & .card:nth-child(1) { grid-column: 1/2; }           /* pequeno: col 1 */
  & .card:nth-child(2) { grid-column: 2/4; }           /* grande: cols 2-3 */
  & .card:nth-child(3) { grid-column: 4/5; }           /* pequeno: col 4 */

  /* Linha 2 */
  & .card:nth-child(4) { grid-column: 1/3; grid-row: 2/3; } /* grande: cols 1-2 */
  & .card:nth-child(5) { grid-column: 3/5; grid-row: 2/3; } /* grande: cols 3-4 */
}

O uso de nth-child para posicionar cada card é o padrão mais limpo: o HTML não precisa de classes extras, e o CSS declara explicitamente onde cada card vai no grid.

3

Posicionamento das imagens dentro dos cards grandes

/* Card 2: imagem no canto inferior direito */
& .card:nth-child(2) {

    right: 2rem;
  }
}

/* Card 4: imagem no canto inferior esquerdo */
& .card:nth-child(4) {

    max-width: 16rem;
    margin-left: auto;             /* texto empurrado para a direita */
  }
  & .desktop-only {
    bottom: 2rem;
    left: 2rem;
  }
}

/* Card 5: imagem no canto superior direito */
& .card:nth-child(5) {
  & > div { max-width: 16rem; }

Ícones sociais com CSS variável (social.css)

Cada ícone social usa aria-label para selecionar a imagem certa via seletor de atributo CSS. 

a.social {
  --bg-img: '';             /* variável local: começa vazia */
  background-image: var(--bg-img);
  width: 1.5rem;
  height: 1.5rem;
  display: block;

  /* Seletores por aria-label: cada rede tem seu SVG */
  &[aria-label='tiktok'] {
    --bg-img: url(../assets/icons/tiktok.svg);
    &:hover { --bg-img: url(../assets/icons/tiktok-hover.svg); }
  }

  &[aria-label='instagram'] {
    --bg-img: url(../assets/icons/instagram.svg);
    &:hover { --bg-img: url(../assets/icons/instagram-hover.svg); }
  }

  /* ... twitter, discord */
}

CSS aninhado nativo (sem Sass): o sinal & dentro de uma regra CSS nativa se refere ao seletor pai. Funciona em todos os browsers modernos desde 2023.

Referência rápida

Padrões CSS avançados usados neste projeto

CSS Nesting (aninhamento nativo)

Usado em quase todos os arquivos CSS do projeto. Evita repetir seletores e agrupa estilos de um componente no mesmo bloco. 

#hero {
  text-align: center;

  /* & = o próprio #hero */
  & h1 { margin-top: 1rem; }
  & p  { color: var(--text-color-secondary); }
  & .buttons { justify-content: center; }
}

@import com media query

O features.css só é carregado em telas largas. Isso mantém o CSS de features completamente ausente no mobile. 

/* index.css */

Seletores de atributo

Seleciona elementos pelo valor de qualquer atributo HTML.

/* Imagem de music-bars (pelo src) */
#hero img[src*='music'] { width: 12.875rem; }

/* Botão com aria-label (técnica do borda gradiente) */
.btn[aria-label] { position: relative; }

/* Ícone social (pelo aria-label) */
a.social[aria-label='tiktok'] { --bg-img: url(...); }

CSS custom properties como estado

Variáveis locais mudam no hover sem duplicar blocos de CSS. 

.btn {
  --btn-bg-color: var(--text-color-primary);

  background: var(--btn-bg-color);
}

/* Hover muda só a variável */
.btn:hover {
  --btn-bg-color: linear-gradient(...);
}
