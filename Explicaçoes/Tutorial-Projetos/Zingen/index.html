Tutorial mobile-first

Como reconstruir o Zingen comecando pelo celular

Voce ja construiu o Zingen comecando pelo desktop. Agora vamos recomecar do zero usando a abordagem mobile-first: escrever o CSS base pensando na tela de 375px e depois usar @media (min-width: ...) para crescer ate o desktop. Este tutorial explica cada passo com exemplos reais do projeto.

Mentalidade

Por que comecar pelo celular?

No seu codigo atual voce escreveu valores como max-width: 1280px, grid-template-columns: repeat(4, 1fr) e height: 43.75rem direto no CSS base. Isso significa que o celular recebe todo o CSS de desktop e depois precisa desfazer tudo com media queries. E como vestir um terno para depois tirar as pecas ate ficar de bermuda.

❌ Seu codigo atual (desktop-first)

O CSS base ja vem com grid de 4 colunas, alturas fixas e max-width de 1280px. No celular, voce precisaria desfazer tudo. 

/* CSS base: pensado para desktop */
#features-section {
  grid-template-columns: repeat(4, 1fr);
  max-width: 1280px;
  padding: 5rem 2rem;
}

/* Depois: desfazer no celular */
@media (max-width: 767px) {
  #features-section {
    grid-template-columns: 1fr;
    padding: 2rem 1rem;
  }
}

✅ Mobile-first (o que vamos fazer)

O CSS base e simples: 1 coluna, tudo empilhado. Depois voce adiciona colunas e espacos conforme a tela cresce. 

/* CSS base: pensado para celular */
.features {
  display: grid;
  gap: 1rem;
  padding: 2rem 1rem;
}

/* Depois: adicionar no tablet/desktop */
@media (min-width: 768px) {
  .features {
    grid-template-columns: repeat(2, 1fr);
    padding: 3rem 2rem;
  }
}

@media (min-width: 1024px) {
  .features {
    grid-template-columns: repeat(4, 1fr);
    padding: 5rem 2rem;
    max-width: 1280px;
    margin: 0 auto;
  }
}

Regra de ouro: no mobile-first, o CSS base e o mais simples possivel. Voce so adiciona complexidade. Nunca precisa desfazer nada.

│   ├── Logo.svg
│   ├── Music-bars.svg
│   ├── App mockups.svg
│   ├── Tela 1.svg

├── styles/

│   ├── nav.css         ← navegacao

│   ├── about.css       ← conhca o app

Passo 1 – CSS base

Escreva o global.css pensando no celular

As variaveis ja sao as mesmas que voce usou. A diferenca e que as fontes base serao as mobile, nao as desktop.

1

Variaveis e reset

Note que as fontes base sao as de mobile. O desktop vem depois dentro de um @media. 

* {
  padding: 0;
  margin: 0;
  box-sizing: border-box;
}

:root {
  /* Cores */
  --brand-primary: #F7B733;
  --brand-secondary: #FC4A1A;
  --bg: #09090B;
  --surface: #18181b;
  --stroke: #27272a;
  --text-primary: #F4F4F5;
  --text-secondary: #A1A1AA;
  --font: 'Inter', sans-serif;

  /* Tipografia mobile (BASE) */
  --h1: 800 2.5rem/120% var(--font);
  --h2: 800 1.5rem/120% var(--font);
  --h3: 800 1.25rem/120% var(--font);
  --span: 500 .875rem/100% var(--font);
  --paragraph: 400 1rem/160% var(--font);
}

body {
  background-color: var(--bg);
  color: var(--text-primary);
  font-family: var(--font);
  overflow-x: hidden;
}

a {
  list-style: none;
  text-decoration: none;
  color: var(--text-primary);
}

img {
  max-width: 100%;  /* ← ESSENCIAL para mobile! */
  height: auto;
}

Diferenca do seu codigo atual: voce tinha --desktop-h1 e --mobile-h1 separados. Agora a base ja e mobile. No @media voce vai sobrescrever as variaveis para desktop.

2

Sobrescrever tipografia no desktop

Quando a tela crescer, voce atualiza as variaveis. Todo o site que usa var(--h1) vai mudar automaticamente. 

/* No final do global.css */
@media (min-width: 1024px) {
  :root {
    --h1: 800 4rem/120% var(--font);
    --h2: 800 3rem/120% var(--font);
    --h3: 800 2rem/120% var(--font);
  }
}

Isso e poderoso: voce muda UMA variavel e TODOS os h1, h2, h3 do site inteiro se ajustam. Sem precisar escrever media query em cada section.

Passo 2 – Navegacao

Comece pela nav: simples no celular, completa no desktop

No celular, a nav mostra so a logo e um botao de menu. No desktop, os links aparecem em linha. O segredo: escreva o HTML completo (com todos os links) e use CSS para esconder o que nao cabe no celular.

1

HTML da nav (igual para mobile e desktop)

<nav class="main-nav">
  <a href="index.html" class="logo">
    <img src="assets/Logo.svg" alt="Zingen">
  </a>

  <div class="nav-links">
    <a href="#about">Conheca o app</a>
    <a href="#features">Funcionalidades</a>
    <a href="#pricing">Planos e precos</a>
    <button class="btn-primary">Baixar agora</button>
  </div>
</nav>
2

CSS mobile (base)

No celular, esconda os links e mostre so a logo.

/* nav.css – base mobile */
.main-nav {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 1rem;
}

.nav-links {
  display: none;  /* escondido no celular */
}

No celular do Figma, a nav mostra so a logo. Os links so aparecem no desktop. Por isso display: none na base e o certo.

3

CSS desktop (min-width)

Quando a tela cresce, mostra os links em linha.

/* nav.css – crescendo para desktop */
@media (min-width: 768px) {
  .main-nav {
    padding: 1.5rem 2rem;
    max-width: 1280px;
    margin: 0 auto;
  }

  .nav-links {
    display: flex;      /* aparece! */
    align-items: center;
    gap: 2rem;
  }

  .nav-links a {
    color: var(--text-secondary);
  }

  .nav-links a:hover {
    background: linear-gradient(90deg, #FC4A1A, #F7B733);
    background-clip: text;
    color: transparent;
  }
}

Esta e a secao mais complexa. No desktop, o Figma mostra um grid de 4 colunas onde os cards "grandes" ocupam 2 colunas. No celular, tudo vira 1 coluna.

  font: var(--paragraph);

Repare que as imagens sao escondidas (display: none) no mobile, pois nao existem no design do celular! No desktop-first muitos cometeriam o erro de carregar as imagens na base e depois esconde-las. No mobile-first, voce esconde na base e adiciona (display: block) no desktop.

Passo 7 – Componentes

Botoes: componentes nao mudam com a tela

Botoes sao componentes. Eles funcionam igual em qualquer tamanho de tela. Nao precisam de media queries.

1

buttons.css (sem media query)

/* buttons.css – funciona em qualquer tela */
.btn-primary {
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
  border: none;
  background-color: var(--text-primary);
  color: var(--bg);
  font-weight: 700;
  cursor: pointer;
  font-family: var(--font);
}

.btn-primary:hover {
  background: linear-gradient(90deg, #FC4A1A, #F7B733);
  color: var(--text-primary);
}

.btn-outline {
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
  border: 2px solid var(--text-primary);
  background-color: transparent;
  color: var(--text-primary);
  font-weight: 700;
  cursor: pointer;
  font-family: var(--font);
}

Componentes isolados (botoes, badges, labels) normalmente nao precisam de @media. Eles se adaptam porque o pai controla o layout, nao o componente.

Passo 8 – Imports

O index.css importa tudo na ordem certa

/* styles/index.css */
@import url(global.css);
@import url(buttons.css);
@import url(nav.css);
@import url(hero.css);
@import url(about.css);
@import url(features.css);
@import url(pricing.css);
@import url(footer.css);

A ordem importa! global.css vem primeiro porque define as variaveis que todos os outros usam. buttons.css vem antes das secoes porque as secoes usam os botoes.

Padrao mental

O padrao que se repete em todas as secoes

Depois de praticar, voce vai perceber que mobile-first segue sempre o mesmo fluxo mental. Aqui esta o padrao que voce pode aplicar em qualquer secao de qualquer projeto:

1. Base mobile

  • display: flex com flex-direction: column
  • ou display: grid com 1 coluna (sem definir colunas)
  • padding horizontal pequeno: 1rem
  • sem max-width
  • sem height fixo
  • imagens com max-width: 100%
  • botoes com width: 100%

2. Crescer com @media

  • @media (min-width: 768px) → adicionar colunas
  • flex-direction: row
  • padding maior: 2rem
  • @media (min-width: 1024px) → layout completo
  • max-width: 1280px + margin: 0 auto
  • alturas fixas so quando necessario
  • position absolute so quando necessario

Decore esse padrao: column → row, 1 coluna → varias colunas, padding pequeno → padding grande, sem max-width → com max-width. Se voce seguir isso em toda secao, nunca mais vai ter duvida de como comecar.

Aprendizados

O que mudar do seu Zingen atual

Comparando o seu codigo atual com a abordagem mobile-first, aqui estao as principais diferencas para voce entender o que faria diferente agora:

Seu codigo atual

  • --desktop-h1 como variavel base
  • max-width: 1280px em todas as secoes
  • height: 43.75rem fixo no hero
  • grid-template-columns: repeat(4, 1fr) na base
  • imagens com larguras fixas em rem
  • sem nenhum @media escrito
  • nesting CSS com & (avancado)

Mobile-first

  • --h1 base e mobile, desktop sobrescreve
  • max-width so aparece no @media desktop
  • hero sem altura fixa, conteudo define
  • grid comeca com 1 coluna, cresce no @media
  • imagens com max-width: 100%
  • @media com min-width em cada arquivo
  • CSS plano, sem nesting (mais legivel)
Checklist

Ordem para voce praticar do zero

  1. Crie a pasta Zingen-Mobile com a estrutura de pastas
  2. Copie os assets do Zingen antigo (SVGs e icones)
  3. Escreva o global.css com variaveis mobile e img { max-width: 100% }
  4. Escreva o buttons.css (nao precisa de media query)
  5. Monte o HTML completo com classes semanticas
  6. Estilize a nav – escondendo links no mobile, mostrando no desktop
  7. Estilize o hero – empilhado, centralizado, sem altura fixa
  8. Estilize o about – column no mobile, row no desktop
  9. Estilize o features – 1 coluna → 2 colunas → 4 colunas
  10. Estilize o pricing – 1 coluna → 3 colunas
  11. Estilize o footer – empilhado no mobile, colunas no desktop
  12. Teste em 3 larguras: 375px, 768px e 1280px
  13. Compare com o Figma em cada tamanho

Use o DevTools do Chrome (F12 → toggle device toolbar) para testar cada tamanho. Comece pelo menor e va aumentando. Se o layout funcionar no 375px e no 1280px, provavelmente funciona em tudo.

Resumo final

As 5 regras do mobile-first

  1. CSS base = celular. Tudo empilhado, 1 coluna, padding pequeno.
  2. Usar min-width. Nunca max-width. Sempre crescer, nunca encolher.
  3. Ordem crescente. 768px antes de 1024px antes de 1280px.
  4. Adicionar, nao desfazer. Se voce esta escrevendo display: none ou resetando valores no @media, provavelmente esta fazendo desktop-first.
  5. Testar pelo celular primeiro. Abra o DevTools em 375px e so depois aumente.
